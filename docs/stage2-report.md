## 4. 실제 사용 흐름 점검(코드)

- **값을 바꾸면 결과·그림·NC 가 함께 바뀌는가**: 그렇다.
  - `SlopeScreen` 은 상태(`TaperState`)의 글을 그때그때 읽어 `SlopeForm`(data class)을 만들고, `remember(form) { TaperSolve.solve(form) }` 로 푼다.
  - 보정 좌표 카드, 형상 뷰어, NC 카드가 모두 같은 `sol` 을 쓴다. 칸 하나가 바뀌면 form 이 달라져 셋이 같이 다시 그려진다.
  - 형상 뷰어는 `remember(bounds)` 라서 모양이 바뀌면 자동 맞춤으로 돌아간다.
  - 홈(`GrooveInput`)·라운드(`RoundInput`/`Arc3Input`)·삼각형(`TriangleInput`)도 같은 방식이다.
- **잘못된 입력에서 죽지 않는가**: 1절 1~3번에서 고쳤고 `InputRobustnessTest` 로 지킨다.
  - 노즈R 칸이 비면 NaN 이 들어가고, 계산기가 `BAD_INPUT` 으로 멈춘다.
  - 0 으로 나누기는 각도 0°·90° 를 `BAD_ANGLE` 로 막는다. 같은 점·수평/수직인 경사도 `BAD_ANGLE` 이다.
  - 홈 피치 0 은 `OVERLAP_TOO_BIG`(겹침 ≥ T)로 막는다.
- **키패드 − · . 처리**(`NumEdit`, `NumEditTest`):
  - −: 맨 앞 부호를 바꾼다. 열자마자 누르면 원래 값의 부호를 바꾼다.
  - .: 한 번만 들어간다. 빈칸에서 누르면 "0." 이 된다.
  - 확인: "5." → "5", "-0" → "0", "−" 만 남으면 빈칸이 된다.
  - 자릿수: 12자리까지 받는다. 그래서 크기 한도가 필요했다.

## 5. 우리가 정한 것 (2단계 전체)

계산:
- **좌표 약속**: Z 오른쪽 +, X 위 +(후방 공구대 그림). 내부는 반경값, 화면 입출력은 직경값.
- **팁 0~9 방향**: Haas 공식 워크북 69~70쪽 표를 따랐다(T3 외경 표준, T4 외경 역, T2 내경, T1 내경 역).
- **G02/G03**: 이 그림에서 G02 = 시계. Haas 워크북 예제로 맞춰 봤다.
- **보정 해법**: 오프셋 → 노즈 원이 재료와 안 겹치는 구간 → 교점으로 잇는다. 틀린 숫자 대신 멈춤 경고를 낸다(NOSE_UNREACHABLE·BAD_LEG 등).
- **NC 두 가지**: 기본은 **G41/G42 보정 프로그램**(도면 좌표, 첫 줄 `(R T)`), 다른 하나는 **직접 보정(G40)**.
  - 직접 보정은 시작·끝에서 인선을 그 좌표에 둔다.
  - G41/G42 의 진입은 직선 이동에서만 한다. 바이트 반대쪽 요소면 노즈가 박히지 않게 G00 점을 띄운다.
- **홈**: NC 는 하나다. 벽·바닥 보정량이 0 이고, 반대 벽은 다른 날 모서리가 깎기 때문이다. G75 처럼 마지막 단만 벽에 맞춘다.
- **라운드 치수 해석**: 주 R 은 중심이 축 위인 구로 본다. 비울 수 있는 묶음에서 하나까지 비울 수 있다. L2 는 A/B 로 고른다. 양쪽 모서리 R 은 같다.
- **90° 넘는 원호**: 같은 각으로 나눠 쓴다(R 지령 반올림 오차 때문).
- **크기 한도** `MAX_MM` = 10 000 mm(이번 점검).

화면:
- **화면의 역방향** = "그림을 좌우로 뒤집은 형상". Z 를 뒤집어 계산기 정방향으로 풀고 되돌린다(`TaperSolve`·`Mirror`). 계산기 reverse 와 숫자·두 NC 글자까지 같은지 시험으로 확인했다.
- **글꼴**: Noto Sans KR + 고정폭 JetBrains Mono(3단계 Z2 에서 Courier Prime 대신). 라이트는 원본 Tailwind 색이고, 다크는 우리가 만들었다.
- **빈칸 표시**: 빈칸은 계산값을 흐리게 보이고 "자동" 배지를 단다. 시작점만 "안 깎음"(이번 점검).
- **고른 칸 글자색**: 바탕 밝기로 고른다(`onFill`, 이번 점검).
- **화면 글**: 모두 한글이다. 바꾼 표는 `screens.md` 첫머리에 있다.

## 6. 남은 문제 (사람이 확인할 것)

먼저 확인할 것(가공 결과에 영향):
1. **FANUC 보정 시작 블록 동작**은 공식 매뉴얼로 확인하지 못했다.
   - Haas 워크북 62쪽 규칙("시작 이동 끝에서 보정 완료", 안쪽 모서리 = 교점)으로 모델링했다.
   - 기계 매뉴얼(B-64304 등 Start-up 절)로 한 번 맞춰 볼 것.
   - FANUC Type A 가 안쪽 모서리에서도 다음 블록 법선을 쓴다면, 단면 시작에서 노즈가 시작 X 보다 r 아래로 내려간다.
2. **G41/G42 프로그램의 끝 블록**: 노즈 접점이 끝좌표에 온다. 그래서 끝 요소가 수평이면 인선이 직접 보정보다 노즈R 만큼 더 간다.
   - 안내 문구만 넣었다.
   - 바로 뒤에 턱이 있는 도면에서는 직접 보정을 써야 한다. 현장에 알려 줄 것.
3. **역방향 해석**("그림을 좌우로 뒤집은 형상")은 원본 앱 사진으로 확인되지 않았다. 원본 앱을 직접 눌러 볼 수 있으면 확인할 것.
4. **라운드 치수 해석**은 원본 입력 화면 사진이 없어서 우리가 정했다.

## 8. 3단계 추가 — 내경 라운드 R + 보링바(홀더) 간섭 확인 (2026-10-21)

사용자 요청(2026-10-20): "내경 라운드는 홀더 크기를 감안해서 공구가 소재에 닿는걸 확인할 수 있게 해야 해".
IR-1 계산(내경 TYPE 2~6 · NC 줄 ↔ 요소), IR-2 보링바 간섭 검사(뒤보링 포함, 독립 표본 검증), IR-3 화면, IR-4 점검 · 문서 · 스크린샷으로 넣었다.
계산은 `calc-design.md` 의 "내경" · "보링바 간섭 검사" 절, 화면은 `ui-design.md` 의 "내경 라운드 · 보링바 간섭" 절.

### 8.1 물어본 것과 답 (2026-10-20)

| # | 물음 | 기본안 | 사용자 답 → 만든 것 |
|---|---|---|---|
| D1 | 내경에서 형상 2 · 4(입구보다 안쪽이 넓은 공 모양 — 언더컷)도 고를 수 있게 둘까 | 형상 2~6, 2 · 4 는 '언더컷' 표, 형상 1 은 없음 | **형상 2~6 + 3점호** — 기본안 그대로 |
| D2 | 내경 3~6 은 입구 원통 깊이(Z0 ~ 첫 이음점)와 전체 깊이(Z0 ~ 바닥) 가운데 무엇을 넣을까 | 입구 원통 깊이 | 기본안 — '입구 구멍 깊이' 칸(실제 치수) |
| D3 | 형상 5 · 6 내경 기본을 막힘(바닥 면까지)과 관통 가운데 무엇으로 | 막힘 + 스위치 | **막힘 + 관통 스위치** — 기본안 그대로 |
| D4 | 내경 프로그램 끝에 빠지는 블록(G00 X… → G00 Z…)을 넣을까 | 넣지 않음 | 기본안 — 외경과 같이 넣지 않음 |
| D5 | 보링바 간섭은 빨간 띠(계산 멈춤과 같은 색)와 노란 띠 가운데 무엇으로 | 노란 띠 + 빨간 표시 | **노란 띠 + 빨간 표시** — 기본안 그대로(숫자 · NC 는 그대로 나온다) |
| D6 | 인서트 각도를 절입각 κr(카탈로그 KAPR)과 끝날각 κr′ 가운데 무엇으로 받을까 | κr | 기본안 — κr 을 받고 κr′ = 180° − κr − ε 를 보인다 |
| D7 | 프리셋의 인서트 날 길이를 품번 크기 숫자(07 → 7 mm)로 넣을까(실제는 0~1 mm 더 길다) | 크기 숫자 | 기본안 — 출처를 확인한 28 줄(샌드빅 16 · 미쓰비시 9 · 한국야금 3), 이스카는 KAPR 이 없어 뺐다 |
| D8 | 뒤보링(역방향 내경)도 홀더 검사가 필요한가 | 이번엔 안 함 | **검사함 — 기본안과 다름**: 인서트를 Z 로 뒤집고(팁 1) 바는 +Z 로 나가는 단면, 독립 검증에 뒤보링 무작위 150. 뒤보링 바 프리셋은 출처가 없어 넣지 않았다 |
| D9 | 내경 R 홈(중심이 축 밖) · 입구 R 을 따로 형상으로 만들까 | 안 만듦 | 기본안 — 입구 R 은 3점호 내경으로 |

### 8.2 IR-4 점검에서 고친 것

| 문제 | 고친 내용 |
|---|---|
| 팁 번호를 외경 · 내경 TYPE 화면이 함께 써서, 외경에서 고른 팁(예 4번)이 내경 보링(G41)에 그대로 들어갔다 | 팁을 외경 · 내경 따로 둔다(테이퍼도 가공 종류마다 따로) — `RoundStateTest.tipPerSide` |
| 뒤보링 경고 글의 '인선에서 … mm 뒤' 가 정방향 기준(+Z = 뒤)이라 뒤보링에서는 거꾸로였다 | 이송 방향 기준으로: 뒤보링은 +Z 가 앞 — `backBoringSaysAhead` |
| 기계 보정 보기에서 형상 확인의 빨간 경로 구간이 보정 경로의 길이 비율을 도면 좌표 경로에 그대로 써서 ✕ 표 · 띠의 좌표와 어긋날 수 있었다 | 노즈가 닿는 도면 점 사이로 자른다(직접 보정은 가상 인선) — `contactBandFollowsShownPath` |
| 형상 확인 '크게 보기' 에서 보링바 자리 알약이 없어 자리를 바꿀 수 없었다 | 크게 보기에도 단추 줄 아래 같은 알약(`round-inner-holder-full` 스크린샷) |
| 내경 그림의 긴 길이 이름('입구 구멍 깊이 10', 'L2 7.342')이 치수보다 길면 오른쪽 보조선이 글자 사이로 지나갔다 | 그 보조선을 이름 위에서 끊는다 |
| 겹친 곳 그림을 키패드가 열리고 닫힐 때마다 다시 셌다 | 자리 · 바가 바뀔 때만 센다 |

### 8.3 남은 것 (사람이 확인할 것)
1. 단면 검사는 둥근 바 자루만 정확하다. 인서트 아래쪽 · 헤드 앞 모양은 최소 가공경(DMIN)으로만 본다 — 실제 바의 헤드가 카탈로그 그림과 다르면 확인할 것.
2. 진입점까지 오는 길 · 가공 뒤 빠지는 길, 황삭 전 소재(예비 구멍)는 보지 않는다.
3. 프리셋은 제조사 카탈로그(사이트 · PDF) 값이다. 같은 이름의 바도 제조사마다 f · DMIN · κr 이 다르니 가진 공구와 맞춰 볼 것.
4. 날 길이를 품번 크기 숫자로 넣어 실제보다 0~1 mm 짧다(D7) — 끝날 쪽 닿음이 아슬아슬하면 실제 날 길이를 넣을 것.
5. 돌출 길이 하한(헤드 길이)은 정방향 바 모양으로 잰다 — 뒤보링도 같은 하한을 쓴다(실제 바도 헤드보다 짧게 물릴 수 없다).
