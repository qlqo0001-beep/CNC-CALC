**견고성 시험 `Stage3RobustnessTest`** (`InputRobustnessTest` 와 같은 방식)
- **흔드는 값**: 키패드로 칠 수 있는 글이다. 빈칸 · 0 · −0 · '.' · '-' · 음수 · 12자리 큰 수 · 0.00000000001 · 0.00001 · 한도 ±10000 근처 · 맞변 절반에 붙은 R 을 넣는다. 고르는 칸(나사 종류 · 사이즈 · 급수 · 소재 · 방향 · 각도 · 면취량 · 도형 · 외/내측 · X 직경/반경 · 메이커 · 시리즈 · 피삭재 군 · 행 · 탭)과 Vc/n · f/fz 기준 바꾸기도 섞는다.
- **`thread` · `polar` · `cutting`**: 각 2만 가지를 계산한다. 화면이 쓰는 글 함수를 모두 부른다(경고 글 · 결과 칸 · 키패드 한 줄 · G76 낱말과 NC 글 · 나사 단면 자료 · 극좌표 그림 · 시뮬레이션 계획 · 드릴 표 · 행 목록 · 출처 줄). 예외가 없고 찍는 숫자 · 그림 점이 모두 유한한지 본다. 풀린 사례는 각 5천 개가 넘어야 통과한다.
- **`drawRandom`**: 무작위 상태 120개 × 세 화면을 `ImageComposeScene` 으로 실제로 그린다. 키패드 열림 · 다크 · 직접 보정 · 시뮬레이션 모달 · 탭 셋을 섞는다.
- **`drawExtremes`**: 칸마다 극단 값 하나씩(12자리 ± · 0.00000000001 · 0 · '-')을 넣고, 나머지 칸은 그럴듯한 값으로 둔 화면을 그린다. 나사 10칸 · 극좌표 8칸 · 절삭 12칸이다.
- **결과**: 1번(극좌표) 말고는 예외가 없었다.
- **잡지 못하는 것**: 유한하지만 터무니없는 숫자는 잡지 못한다. 예를 들어 지름 0.0000000001 · Vc 1000000 이면 회전수가 10¹⁸ 단위로 나오고, 더 큰 분당 이송은 화면 글(`fixed`)이 Long 끝에서 멈춘 수를 보인다. 계산기 한도(10000 mm · 1000000) 안의 값이지만 현장 입력으로는 생기지 않을 값이라 그대로 두었다(5절).

## 3. 정한 것 (세 기능 공통)

- **빈칸 시작**(사용자 결정)
  - 도면 값(나사의 사이즈 · Z 시작 · 목표 Z · 첫 절입, 극좌표의 외경 · W · 공구경 · 깊이 · F, 재료의 모든 칸 · 드릴 고르기)은 빈칸이면 계산하지 않는다. 대신 파란 '남은 것' 을 보인다.
  - 가공 값은 빈칸이면 정해진 기본값으로 계산하고 자리표시로 알린다. 나사는 '기본 80' 등, 극좌표는 코너 R · 회전 0 · 여유 1, 재료는 날 수 2 · G50 S '안 씀' 이다.
  - 범위 밖 값은 계산기 BAD_INPUT 과 같은 규칙으로 바로 빨간 테를 친다.
- **출처 없는 값은 넣지 않았다**: 나사 추천 회전수 · 첫 절입 · 절입 횟수, 극좌표 공구경 · 이송 기본값, 선삭 재질별 Vc, 대구텍 · Gühring · OSG 자료, 원본 03 의 날 수 고르기.
- **보정 방식**: 극좌표는 앱 전체 스위치(기계 보정 G41 / 직접 보정 G40)를 따른다. 결과 · NC · 시뮬레이션이 모두 따라간다. 나사 G76 은 노즈R 보정을 쓰지 않아 스위치가 없다.
- **극좌표 G12.1 안 X 지령**: 직경 / 반경을 고르게 했다(기본 직경). FANUC 매뉴얼끼리도 다르고, 기계 매개변수마다 다르다. 화면 상태라 기억하지 않는다.
- **나사 공차**: 미터는 ISO 965 표 값이고, 표가 없는 칸(4h · 8g 와 몇 곳)만 식이다. 식을 쓴 칸은 파란 안내를 띄운다. UN 은 ASME B1.1 식이다. 기본 급수는 6g/6H · 2A/2B 다.
- **G76 단위**: P(k) · Q 는 μm 정수(IS-B 기계 가정), R(d) 는 mm 소수, F 는 0.0001 까지다. IS-C 기계 주의를 NC 카드 설명에 적었다.
- **드릴 결과**: 카탈로그 값 그대로다. 이송은 구간 값이고 보간하지 않는다. 권장이 없으면 만들지 않는다. 회전수 표 행은 표 회전수를 쓰고 Vc 는 환산이다. 깊이 · 급유 각주의 감소율은 글로만 보인다.
- **이번 점검에서 정한 것**
  - 극좌표 코너 R 0.000001 mm 미만은 0 으로 본다(1절).
  - 이 보고는 같은 이름의 10-22 보고 위에 붙였다. 지시된 파일 이름을 지키면서 앞 보고를 잃지 않으려고 그렇게 했다.

## 5. 남은 문제

**가공 전에 기계에서 한 번 확인할 것**
- 나사 G76
  - 역가공(Z+): FANUC 매뉴얼 그림이 모두 Z− 다. 화면은 파란 주의만 띄운다.
  - IS-C(0.0001 mm) 기계: P · Q 를 10배로 읽는다. NC 카드 설명에만 적었다.
- 극좌표
  - G12.1 안 X 직경/반경, 시작점 `C0.`, G41 시작 · 취소 경로는 실제 기계로 확인하지 못했다. 화면이 '첫 가공은 싱글 블록' 을 안내한다.
  - 중심 근처 C 축 이송 한도(F < L·R·π/180)는 기계의 C 축 최대 이송을 몰라 경고하지 않는다.
- 미터 4h · 8g 와 M1~M1.4 6H · 6G 의 일부: 공차 표가 없어 식으로 낸다. 목표 100% 가 표 한계를 몇 μm 넘을 수 있다(파란 안내).
- UN 3B/2B 0% 목표: 구멍이 기본 안지름 그대로다. 인쇄된 H28 값(.1960 in)으로 만든 GO 게이지와 약 3 μm 차이가 날 수 있다.

**안 한 것(출처 · 범위)**
- 나사: 관용 테이퍼 나사(PT · NPT), 미터 6e · 6f · 4H · 5H · 7H, 여러 줄 나사, 인치 지령(G20), 추천 회전수 · 첫 절입 · 절입 횟수(출처 없음). 면취량은 0.0P~2.0P 까지다(FANUC 은 9.9P) — 더 필요한지 현장 확인이 필요하다.
- 극좌표
  - 살이 공구경보다 두꺼울 때 여러 바퀴 깎기(`STOCK_LEFT` 경고만), Z 여러 단, 하향/상향 고르기는 하지 않았다.

## 2. 계산 엔진에서 바뀐 것

모두 사용자가 승인했거나, 점검에서 결함으로 확인된 것이다. 하나마다 calc 시험을 더했다.

- **테이퍼**
  - Z 여유 0 을 허용한다(노즈 R·Z 여유 둘 다 0 이면 `BAD_INPUT`).
  - 진입은 Z 로 max(Z 여유, r)이다.
  - 끝점을 비우면 마지막 점에서 끝나고, 후퇴 규칙도 그에 맞췄다.
  - `NOSE_GT_SLOPE` 는 짧은 경사의 한 끝이 오목할 때만 띄운다. 볼록-볼록 면취의 헛경고를 없앴다.
- **라운드**: 진입 max(Z 여유, r). 내경 형상 2~6 을 넣었고, NC 줄과 요소를 잇는 `ncRefs`/`lineOf` 를 더했다.
- **Fmt**: 90° 를 0.09° 미만으로 넘는 원호(CAD 넷째 자리로 넣은 1/4 원)는 R 블록 하나로 쓴다.
- **보링바 간섭(`Holder.kt`)**
  - 인서트·바·공구대·최소 가공경을 보고, 뒤보링도 포함한다.
  - 다른 방법(조밀 표본)으로 따로 검증하는 시험을 두었다(`HolderVerifyTest`).
- **직각삼각형**: 다른 계산기처럼 10 000 mm 한도를 둔다. 아주 큰 값에서 틀린 숫자가 경고 없이 나오던 것을 막았다.

## 3. 화면에서 달라진 것

- **그림**
  - 테이퍼·홈·라운드·삼각형 그림을 한 규칙(`DrawKit`)으로 다시 그렸다: 소재 빗금, 회전축 중심선, 굵은 윤곽과 가는 치수선, 화살표 치수.

  - 이송 방향 화살표와 시작·끝 표시를 넣었다.
- **형상 뷰어**
  - 한 손가락·휠은 페이지를 스크롤한다(그림이 잡지 않음).
  - −/+/맞춤 단추, 크게 보기를 넣었다.
  - 라벨은 알약 모양이고 겹치지 않게 자리를 고른다.
  - 내경은 지름 전체 단면, 보링바 윤곽, 간섭 빨간 칠과 NC 줄 번호를 보인다.
- **키패드**: 1절의 덮어쓰기·즉시 반영·'다음'. 키패드 안 작은 그림에 지금 고치는 치수를 짚고, 결과 한 줄도 보인다.
- **결과·NC**
  - 계산이 멈추면 이유를 위쪽과 해당 칸(빨간 테)에 보인다.
  - 값이 서로 안 맞으면 '… 비우고 계산' 단추로 한 번에 고친다.
  - NC 카드는 줄 번호와 이름 붙은 큰 복사 단추를 갖췄다. 아래쪽 결과 띠가 요약을 계속 보인다.
- **앱 틀**: 누르는 자리 48dp 이상, 묶음 도움말 시트, 준비 중 화면 안내. PC 창은 본문 640dp 가운데에 두고 창 크기·자리를 기억한다.
- **글**
  - 고정폭 글꼴을 JetBrains Mono 로 바꿨다(0 과 O, − 가 또렷).
  - 한글은 어절 단위로 줄을 바꾼다.
  - 작은 글은 대비 4.5:1 이상이다(메뉴 단추 포함).

## 4. 확인한 방법

- **계산**: 손 계산·외부 기준값(2단계)에 더해, 3단계에서 바뀐 규칙마다 시험을 넣었다. 내경·간섭은 시험을 먼저 쓰고 구현한 뒤, 표본 검증과 대조했다.
- **화면 숫자**: `UiGoldenTest` 가 모든 시험 화면의 좌표와 NC 를 고정한다. 바꿀 때는 `-DupdateGolden=true` 로, 바뀐 줄을 커밋에 적었다.
- **화면 모양**
  - 시험 화면을 모두 라이트·다크와 큰 글꼴·좁은 폰·넓은 PC 로 찍었다.
  - 두 차례 나눠 살폈고, 나온 문제는 따로 반박 검증한 뒤 고쳤다.
  - 1차는 재설계 전으로, 42건을 확인했다.
  - 2차는 재설계 뒤로, 확인된 것을 고쳤다. 360dp 에서 헤더 제목이 줄어들다 '…' 로 끝나는 한 건만 설계대로라 그대로 두었다.
- **실제 조작**: 만든 PC 앱을 가상 화면에서 실제 마우스·키보드로 눌러 봤다(`stage2-report.md` 6.2). 키패드, 복사, 뒤로, Ctrl+휠, 창 크기 기억을 확인했다.

## 5. 남은 것 (사람이 확인할 것)

- **가공에 영향**: `stage2-report.md` 6절 1~5(FANUC 보정 시작 블록, G41/G42 끝 블록, 역방향 해석, 라운드 치수 해석, 홈 관례)는 그대로다.
